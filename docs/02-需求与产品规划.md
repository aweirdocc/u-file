## 1. 项目定位

**u-file** 是一个可私有化部署的**统一文件管理服务平台**：把散落在各处的文件存储（对象存储、FTP/SFTP、数据库、本地磁盘等）统一接入，通过一个 Web 界面完成文件**浏览、检索、下载与基础管理**。

一句话：**异构存储的统一文件门户 / 文件中台（轻量版）**。

**明确不做的事**（边界，避免范围膨胀）：

- 不做网盘同步客户端（不追求 Seafile/Nextcloud 那种"本地↔云端双向同步"体验）
- 不做在线协同编辑、版本管理
- 不自建存储，只做"接入与聚合"（存储本身交给对象存储/文件服务器）

## 2. 目标用户与典型场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 个人开发者 / 极客 | 手里有 OSS、Cloudflare R2、VPS 上的 FTP/SFTP 等多个存储，想要一个统一入口浏览管理 | 接入简单、单二进制部署、浏览快 |
| 中小企业内部 | 文件散落在对象存储、老系统的 FTP、数据库附件表（BLOB）里，缺少统一查看入口 | 一个文件门户，支持按源授权、审计 |
| 开发 / 运维人员 | 需要排查"某个文件到底在哪、多大、何时更新"，或临时取数 | 跨源搜索、元数据一览、直链下载 |

## 3. 核心概念与术语

| 术语 | 含义 |
|---|---|
| 文件源（Source） | 一个外部存储连接配置：类型、endpoint、凭据、默认根路径 |
| 驱动（Driver） | 某一类文件源的协议适配实现（如 S3 驱动、SFTP 驱动） |
| 能力位（Capabilities） | 该驱动支持的操作集合：列目录 / 下载 / 上传 / 删除 / 重命名 / 生成直链…… |
| 条目（Entry） | 一个文件或目录的元数据（名称、大小、修改时间、ETag 等） |
| 索引（Index） | 平台本地缓存/缓存的目录树元数据，用于加速浏览与搜索 |

**MVP 简化决策**：MVP 阶段"源即挂载点"，每个文件源在界面上以顶层目录的形式呈现（`/我的OSS/...`、`/备份FTP/...`），不引入独立的"挂载"概念；多挂载、跨源移动放到远期（P3）。

## 4. 功能需求（按阶段划分）

### P0 —— MVP（第一期必须做）

1. **源管理**
   - 新增 / 编辑 / 删除 / 列表文件源；添加后即时生效
   - **连通性测试**（保存前可一键测试，返回可读的错误信息）
   - 凭据加密存储，界面上不回显明文密钥
   - MVP 支持类型：**本地磁盘** + **S3 协议族**（AWS S3、MinIO、Cloudflare R2、阿里云 OSS、腾讯云 COS、华为云 OBS、七牛 Kodo、百度 BOS，统一走 S3 接入，预置各家 endpoint 模板）
2. **文件浏览**
   - 目录树 + 文件列表（名称 / 大小 / 修改时间 / 类型图标）
   - 面包屑导航、排序、分页或虚拟滚动（单目录万级条目可浏览）
   - 目录懒加载：点开才列取，带 TTL 缓存与手动刷新
3. **下载**
   - 单文件流式下载，支持 Range 断点续传
   - S3 族源可配置"直链模式"：302 跳转到预签名 URL（省服务器带宽）
4. **元数据索引 / 同步**
   - 目录懒加载缓存 + 后台定时全量同步（可配周期）
   - 同步任务状态可见（上次成功时间、失败原因）
5. **账号与安全基线**
   - 单管理员（用户名密码登录）+ 可选只读访客
   - 登录限速、HTTPS 建议、操作基础日志

### P1（第二期）

6. **FTP / FTPS / SFTP 源**（含密钥认证、host key 校验策略）
7. **上传**：小文件代理直传；大文件分片（S3 multipart / FTP REST / SFTP seek）
8. **管理操作**（按能力位启用）：删除、重命名、新建文件夹
9. **批量操作与打包下载**：多选下载、整目录 zip 流式打包
10. **搜索**：基于索引库的文件名搜索（跨源、模糊/前缀）

### P2（第三期）

11. **数据库源（只读优先）**：MySQL / PostgreSQL 的"文件表"（BLOB/bytea 列 + 名称/大小等元数据列）、PostgreSQL Large Object、MongoDB GridFS
12. **预览**：图片 / 视频 / 音频 / 文本 / Markdown / PDF；图片缩略图
13. **分享外链**：有效期、提取码、下载次数限制
14. **多用户与权限**：角色、源级/路径级 ACL、操作审计日志
15. **WebDAV 服务端**：把聚合后的文件以 WebDAV 协议暴露给第三方挂载

### P3（远期 / 增强）

16. 更多源类型：WebDAV 客户端、Azure Blob / GCS、国内网盘类（按需）
17. 全文检索（内容抽取 + Meilisearch / Tantivy）
18. 传输任务中心：上传/下载/同步任务队列、失败重试、进度面板
19. 开放 API Token、事件 Webhook
20. 多挂载点、跨源复制/移动

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 缓存命中时目录列表 < 100ms；单目录 1 万条目首次列取（分页）< 2s；下载吞吐随网络，网关模式单核 ≥ 100MB/s（Go 流式拷贝可满足） |
| 内存 | 流式传输，**任意大小文件下载不整载内存**（目标峰值 < 200MB） |
| 安全 | 凭据 AES-256-GCM 加密落库；防路径穿越；防 SSRF（endpoint 策略可配）；会话安全 |
| 可用性 | 单二进制 + SQLite 开箱即用；提供 Docker 镜像与 docker-compose 示例 |
| 可扩展 | 驱动插件化接口，新增一种源类型的驱动骨架 ≤ 2 人日 |
| 可观测 | 结构化日志、源健康检查、同步任务状态、审计日志 |
| 兼容性 | 主流现代浏览器近两年版本 |

## 7. MVP 验收标准（示例）

1. 添加一个阿里云 OSS bucket（AK/SK），能在 Web 上逐级浏览目录结构，列取延迟符合性能要求；
2. 通过平台下载 1GB 文件成功，服务端内存占用平稳（< 200MB），且支持浏览器断点续传；
3. 配置错误的源（错 AK、错 endpoint）在连通性测试和浏览时返回**可读**错误提示，服务不崩溃；
4. 重启服务后，已配置的源与缓存索引仍在，凭据可正常解密使用；
5. 未登录访问任何 API 返回 401；普通访客无法执行删除类操作。
